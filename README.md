# 자료실 공개 자료 점검

이 문서는 현재 배포 파일과 GitHub 최신 파일의 가상 메모 문장 검색 절차를 기록합니다. 자료 이전이나 접근 제어가 완료되었다는 증빙은 아닙니다.

## 점검 대상

- 서비스 주소: https://choi-bujang-secret-vault-7zk7.vercel.app
- 앞서 배포에서 확인한 저장소: https://github.com/kjhoping903/aleph-defense-starter
- 현재 로컬 Git 원격: https://github.com/kjhoping903/choi-bujang-secret-vault-5

두 저장소가 다르므로 로컬 원격만 검사해서 배포 소스 검사가 끝났다고 판단하지 않습니다. 매 점검 때 `/aleph.json`의 `repoUrl`과 `commit`을 확인하고 실제 GitHub 저장소 및 커밋과 대조합니다. 최신 기본 브랜치 커밋과 배포 커밋이 다르면 각각 검사하고 차이를 기록합니다.

## 검색할 가상 메모 문장

앞서 배포에서 확인한 메모는 네 건입니다. 세 건만 이전하더라도 공개 파일 점검은 다음 네 문장을 모두 대상으로 합니다.

```text
실습용 가상 과제 기록
실습용 가상 포트폴리오 기록
실습용 가상 리추얼 기록
실습용 가상 행정 기록
```

이 README 자체에 검색 문장이 있으므로 저장소 전체 검색은 README에서도 일치합니다. 이를 숨기거나 검색 결과에서 조용히 제외하지 않습니다. 이전용 SQL에 문장을 넣고 공개 GitHub에 올리면 그 SQL도 공개 노출입니다. 결과에는 경로와 공개 여부를 함께 적습니다.

## 확인 절차

1. 점검 시각을 한국 시간으로 기록합니다. 쿠키와 Authorization 헤더 없이 `/`, `/data.json`, `/aleph.json`을 GET 요청하여 HTTP 상태, 최종 URL, 응답 형식을 기록합니다. 오류나 로그인 리다이렉트는 “문장 없음”으로 처리하지 않습니다.
2. `/` HTML 및 페이지가 참조하는 JavaScript, JSON, 기타 정적 파일의 응답 본문에서 네 문장을 검색합니다. JSON의 유니코드 이스케이프는 JSON 파싱 후 검사합니다. 화면에 보이지 않는다는 사실만으로 정적 파일에서 제거됐다고 판단하지 않습니다. `/data.json`은 직접 요청해서 별도로 검사합니다.
3. `/aleph.json`의 저장소와 배포 커밋을 대조합니다. 별도 임시 폴더에 해당 공개 저장소의 최신 기본 브랜치를 받아 최신 커밋 SHA를 기록합니다. 로컬에 다른 작업이 있으면 덮어쓰거나 reset하지 않습니다.
4. GitHub 최신 커밋의 모든 추적 파일을 검색합니다. 다음 명령은 각 문장을 고정 문자열로 검사하며 파일 경로와 줄 번호를 출력합니다. 종료 코드 0은 일치, 1은 일치 없음, 그 외는 검사 오류입니다.

   ```powershell
   git rev-parse HEAD
   git grep -n -F -e '실습용 가상 과제 기록' -e '실습용 가상 포트폴리오 기록' -e '실습용 가상 리추얼 기록' -e '실습용 가상 행정 기록' HEAD -- .
   ```

5. 새 빌드 결과 폴더에도 같은 네 문장을 검색합니다. 실제 배포 응답과 함께 확인해야 합니다. 빌드 폴더가 없거나 빌드를 하지 않았다면 “미확인”으로 기록합니다. 1단계 확인을 위해 설정 파일 수동 수정이나 `npm run bundle`을 요구하지 않습니다.
6. 공개 API 검사를 검색 검사와 별도로 기록합니다. Supabase 자료 이전 후에는 테이블의 `owner_id uuid`, 외래키 부재, RLS 활성화, `anon`·`authenticated` 읽기 권한 회수, 읽기 정책 유무를 SQL Editor에서 확인합니다. RLS 설정만으로 배포된 모든 API의 접근 제어를 증명하지 않습니다. 서버 API가 높은 권한으로 조회한다면 서버의 인증·인가도 따로 검사합니다. 실제 키나 토큰은 README, 명령 출력, Git에 기록하지 않습니다.

## 검색 결과 기록

아래는 이전 확인 결과이며 이번 문서 작성 시 재검사한 결과가 아닙니다. 새 점검은 별도 행에 시각과 커밋을 기록합니다.

| 점검 대상 | 확인 결과 | 한계 |
| --- | --- | --- |
| 이전 배포 `/data.json` | 비로그인 HTTP 200, 위 가상 메모 네 문장 모두 포함 | 현재 상태 재검사 필요 |
| 이전 배포 `/` | 비로그인 HTTP 200, `/data.json`을 요청하는 코드 포함 | 모든 정적 파일 검색은 미완료 |
| 이전 배포 `/aleph.json` | 저장소 `kjhoping903/aleph-defense-starter`, 커밋 `8a0927400ec0d0a8ff08146db773fec80fb6d216` 확인 | 최신 배포 및 최신 기본 브랜치와 재대조 필요 |
| 위 배포 커밋의 `data.json` | 가상 메모 네 건 확인 | GitHub 최신 파일 전체 검색을 대체하지 않음 |
| 새 정적 빌드 결과 | 미확인 | 현재 폴더에 애플리케이션 소스와 빌드 결과 없음 |
| GitHub 최신 파일 전체 | 미확인 | 최신 SHA 및 전체 검색 결과 기록 필요 |

새 점검 기록 형식: `점검 시각 / 대상 URL 또는 저장소 / 배포 SHA·최신 SHA / HTTP 상태 / 검색 문장 / 일치 경로·건수 / 오류·미확인 범위`.

## 공개 API의 남은 약점 기록

| 항목 | 남은 약점 또는 미확인 사항 |
| --- | --- |
| 공개 정적 데이터 | 이전 점검에서 `/data.json`은 인증 없이 네 메모를 반환했습니다. 현재 응답 재검사 전에는 제거됐다고 기록하지 않습니다. |
| Supabase 테이블 | 이 폴더에서 이전 SQL 및 실행 증빙을 확인하지 못했습니다. `owner_id`, RLS, 권한과 정책은 미확인입니다. |
| 서버 조회 API | API 경로, 인증·인가, 높은 권한을 사용하는 조회 여부는 미확인입니다. |
| 공개 GitHub 문서·SQL | README의 검색 문장과 공개 이전 SQL의 메모도 누구나 읽을 수 있습니다. 데이터 파일 제거와 구분해 기록합니다. |
| 과거 커밋·배포 | 옛 공개 커밋이나 옛 배포 URL에 메모가 남아 있으면 과거 노출은 남아 있습니다. 최신 파일에서 검색되지 않아도 과거 노출이 해소됐다고 쓰지 않습니다. 이미 내려받은 사본의 회수도 보장할 수 없습니다. |

공개 응답의 메모 제거, GitHub 최신 파일의 검색 결과, API 접근 제어, 과거 노출 여부는 각각 독립적으로 기록합니다.
